# Learning features (curriculum, media, progress, notes)

## Objective

Apply the author's learning-features prompt on top of the NestJS rebuild: sections, publication status, page-based content with typed blocks, media storage, page-based progress and student notes.

## Decisions (accepted 2026-10-05)

- **Architecture:** keep the template hexagonal features (`domain/application/infrastructure/presentation`), not `routes/service/repository` files (the prompt's own continuity rule). Keep the template envelope (earlier decision; legacy contracts are not preserved).
- **Content unit:** `Page` + `PageSection` (author decision). `Page` gets a `lessonId` FK; progress becomes "pages viewed". `Step` stays read-only (not deleted). Completed `LessonCompletion` rows are never downgraded. Lessons without pages are reported for authoring.
- **Schema:** additive only; no column drops. Migration SQL generated offline with `prisma migrate diff` (no DB connection), plus explicit data-migration SQL. The author reviews and applies it, and runs before/after count queries.
- **Status:** `ContentStatus { DRAFT, PUBLISHED, ARCHIVED }` on Level, Module, Lesson, Page. Students see only PUBLISHED with published ancestors; others get 404. Teachers/admins see everything.
- **Sections:** new `Section` model; `mecanica` and `ventylab` created from `Level.track`; `Level.sectionId` backfilled. `Level.track` kept for compatibility.
- **Media:** Supabase Storage adapter behind the existing `IFileStorageService` port; env `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET` optional (upload answers 503 when absent).
- **Notes AI:** `NotesAnalyzer` port with an adapter over `IAITextGenerator` (no 501).
- **Clinical cases:** removed from curriculum/progress code; schema columns stay.
- **Execution:** L1 alone; then L2, L3, L5 in parallel (separate feature folders; shared registry files edited last after re-reading); L4 after L2.
