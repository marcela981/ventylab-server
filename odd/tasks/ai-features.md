# AI features: ai, ai-telemetry, ai-tutor, ai-ratings

## Objective
Replace the single Gemini text generator with an AI gateway (provider strategy, per-use-case settings, retries, circuit breaker, consumer-provided deterministic fallback, streaming with abort, quotas from telemetry, versioned prompts), plus telemetry, an AI tutor (page deepen, lesson/module Q&A, topic-restricted free chat, notes analysis adapter) and ratings aligned with QUEST, inside the NestJS hexagonal architecture.

## Phase 1 findings (2026-10-05)
- Only provider: Gemini via `@google/generative-ai@0.24.1` (`src/common/infrastructure/ai/gemini-ai-text-generator.ts`), non-streaming, 6-model fallback chain, 30 s race timeout (SDK call not aborted), linear backoff; `GEMINI_API_KEY` optional and the only AI env var. No OpenAI/Anthropic SDKs installed.
- Consumers: clinical-cases feedback (sync, fallback, prompt not delimited), notes analysis (sync, no fallback, 503/502 — never 501), evaluation grade feedback (async, fallback, delimited).
- No conversation/message/call-log/rating tables; AI output stored only in `grade_feedbacks` and legacy `evaluation_attempts.aiFeedback`.
- No SSE; socket.io gateway exists; global `compression()` would buffer SSE; JWT only from the Authorization header.
- No per-user AI quota; throttler is global per IP.
- Thesis auditors (`scripts/auditors/FeedbackAuditor.ts`, `scripts/audit-e2e/auditors/AIContextAuditor.ts`) scan `gemini-ai-text-generator.ts` for providers and expect `EvaluationFeedbackGenerator` in clinical-cases.

## Decisions (plan accepted by the author, 2026-10-05; defaults chosen by the parent)
1. Structure: NestJS layers per feature (`ai`, `ai-telemetry`, `ai-tutor`, `ai-ratings`); public APIs are module-exported facades. Dependencies: ai -> ai-telemetry; ai-tutor -> ai, pages/curriculum, notes; ai-ratings -> ai-telemetry; notes/evaluation/clinical-cases -> ai through their existing ports.
2. Providers: Gemini migrated to the existing SDK (with streaming); OpenAI and Anthropic implemented over HTTP with `fetch` (no new libraries), registered only when their API key is configured; CustomHttpProvider registered only when endpoint, auth header and mapping are configured; the request/response mapping is a documented, replaceable function (no invented third-party contract).
3. Settings: `AI_SETTINGS_PROVIDER_TOKEN` with a config-backed adapter (per use case: provider chain, model, timeout, maxOutputTokens, temperature; quotas per role and use case; breaker N/M; history window; token budget; prices). Values only from config (`src/common/infrastructure/config/`), never exposed to clients.
4. Streaming transport: SSE over an authenticated POST (`Authorization` header; client reads with fetch streams), events `delta`, `done`, `error`; compression skipped for `text/event-stream`; client disconnect aborts the provider call.
5. Telemetry writes are non-blocking; quotas computed from `ai_call_logs` with a short in-memory TTL cache.
6. Legacy `IAITextGenerator` stays until no file imports it; clinical-cases is rewired last (a concurrent session is fixing its expert-configuration leak). Thesis auditors are updated to point at the new provider files only after the legacy adapter is removed, and any expectation that cannot be met honestly is reported, not faked.
7. Migrations are generated offline and never applied by the agent.

## Constraints
- No git writes; no `npm run`/`npm install`; no DB connection; no `.env*`; no frontend.
- No keys, internal models or system prompts exposed to clients; no personal data sent to providers.
- Mandatory authorship header on every new or modified `.ts` file.

## Acceptance criteria
Prompt checks 1–17; DB/provider-dependent runtime checks are run by the author.
1. `npx tsc --noEmit` → 0 errors.
2. `npx madge --circular --extensions ts src` → no cycles.
3. `npx prisma validate` → valid.
4. No `prisma.` outside `/persistence/` in ai, ai-tutor, ai-telemetry, ai-ratings.
5. Authorship header on every `.ts` under `src/`.
6. No key literal in `src`; no route/DTO returns keys, internal settings or system prompts.
7. Mocked providers: first fails (500) → second answers, attempts = 2; all fail with fallback → source DETERMINISTIC and status FALLBACK in AiCallLog; all fail without fallback → 503; timeout → moves to the next provider within timeout + margin; N consecutive failures → breaker skips that provider for M seconds.
8. Quota exceeded → 429 and a QUOTA_EXCEEDED log row.
9. Free chat with an off-topic question → refusal, no FREE_CHAT call (only TOPIC_CHECK), BLOCKED_OFFTOPIC log row.
10. Deepen a DRAFT page as a student → 404.
11. Client closes the stream midway → call aborted, ABORTED log row, partial message persisted as incomplete.
12. Student A reads B's conversation → 403/404.
13. Payload sent to the provider (capturing mock) contains no student name, email or code.
14. Evaluation feedback and notes analysis work through ai (notes endpoint no longer returns 501).
15. Rating the same response twice → 1 updated row; rating someone else's response → 403.
16. Every successful call produces exactly 1 AiCallLog with promptVersion, tokens, latency and TTFT (in streaming).
17. Legacy service removed: grep for its names in `src` → 0 results.
