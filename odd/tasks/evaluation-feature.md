# Evaluation feature: unified evaluations (exams, quizzes, workshops)

## Objective
Unify quizzes and activities into a single `evaluation` feature (authoring, activation, attempts, grading, AI feedback) inside the NestJS hexagonal architecture, migrating existing data losslessly and keeping legacy HTTP contracts working.

## Decisions (confirmed by the author, 2026-10-05)
1. Option A, additive unification: new tables, data copied with the SAME ids; `quizzes`, `quiz_attempts`, `activities`, `activity_assignments`, `activity_submissions` are frozen (never deleted); legacy routes are rewired internally to the new model without changing their responses.
2. Model names: `Evaluation`, `EvaluationScenario`, `EvaluationQuestion`, `EvaluationQuestionOption`, `EvaluationAssignment`, `StudentEvaluationAttempt` (`EvaluationAttempt`/`evaluation_attempts` already belong to clinical cases), `EvaluationAnswer`, `GradeFeedback`.
3. Mapping: Quiz → QUIZ (JSON questions/options expanded keeping ids); Activity → EXAM/WORKSHOP (`TALLER` → WORKSHOP with `legacyType='TALLER'`); QuizAttempt → GRADED attempt (score kept, grade = round(5*score/100,1), published at completedAt); ActivitySubmission → IN_PROGRESS / PENDING_REVIEW (`isLate`) / GRADED keeping score, maxScore, teacher feedback, raw content in `legacyPayload`; `scores` and `lesson_completions` untouched.
4. One IN_PROGRESS attempt per user and evaluation: advisory lock in the transaction (same pattern as the current quiz guard) plus `@@unique([evaluationId, userId, attemptNumber])`.
5. AI feedback: `GradeFeedbackGenerator` port over the existing `IAITextGenerator` (Gemini, single provider) plus an evaluation-owned deterministic fallback; async via `@OnEvent`; provider logic untouched.
6. `PracticalScoreProvider`: adapter over clinical-cases `compareConfigurations` using the last `SimulatorSession.parametersLog` command; "not available" otherwise (question stays manual).
7. Grade scale 0.0–5.0 with one decimal; passing grade 3.0 from config.
8. Out of scope (reported): clinical-case evaluate endpoint leaks the expert configuration.

## Constraints
- No git writes; no `npm run`; no DB connection; SQL generated offline and applied only by the author.
- No `.env*`; no frontend; no loss or alteration of existing attempts or grades.
- Do not rewrite LLM provider logic.
- Mandatory authorship header on every new or modified `.ts` file.
