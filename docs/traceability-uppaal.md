## Status legend

- **Verifyta**: `satisfied`, `not satisfied` or `not run`.
- **Test**: `present-and-passing` (existed before this document), `added` (new spec under `test/uppaal/`), `missing` (none). Qualifiers: `deviation` (the code intentionally differs from the model; see the divergences), `partial` (the test covers the backend share of a property that also involves the device, the network or the frontend), `proxy` (the property is a statement about the model itself; the test checks the code behavior that corresponds to it).

All tests listed were run on 2026-10-13 and pass (see "Running the tests").

| Topic | Model | Code | Where |
| --- | --- | --- | --- |

## Running the tests

The new specs live in `test/uppaal/`. No Jest configuration picks that folder up yet; until one does, run them with the contract configuration and a root override:

```powershell
npx jest --config test/jest/jest.contract.config.js --roots "<rootDir>/test/uppaal" --runInBand
```

The pre-existing property specs run with the unit configuration:

```powershell
npx jest --config test/jest/jest.unit.config.js --runInBand --coverage=false uppaal- telemetry-pipeline command-lifecycle.service refresh-token.usecase ventilator-room-access create-reservation.usecase login.usecase
```

The timing tests (telemetry S3, S4, S5; commands S5; authentication S4) use the real clock and assert percentiles, so a heavily loaded machine can make them slower; they do not measure the network, the broker or the browser.
